# SFA4D 启动指令文档

## 开始前必读

- ✅ **163 轮权重已随仓库分发**：`checkpoints/sfa3d_8d_full_300epochs/Model_sfa3d_8d_full_300epochs_epoch_163.pth`（48.65 MB）——只想跑推理/可视化可直接看《启动推理指令》《启动可视化指令》
- ❌ **仓库不含数据集**：`./DRadDataset`（需含 `ImageSets/`、`training/`、`testing/`，KITTI 格式）请按赛题官方渠道自备；仓库根目录的 `sample_data/`（3 个样本）仅供核对数据格式
- 所有命令默认在**仓库根目录**执行，conda 环境名 `sfa3d`

## 概述

本文档包含 SFA4D 的训练、恢复训练、导出（ONNX / 量化）等命令。
注：我们训练读取 0,1,2,4 索引的点云，即将第五维信噪比强度 P 作为强度。
维度读取逻辑：
8D 数据：通过 `process_8d_lidar_data_scheme_B()` 读取维度 `[0,1,2,4]`（P 映射为 intensity）
即：8D 数据 `[x,y,z,D,P,R,A,E]` → 读取 `[0,1,2,4]` 维度 → P 映射为 intensity → 输出 4D `[x,y,z,intensity]`

## 训练指令

### 测试训练（3 轮冒烟）

```bash
source activate sfa3d && python sfa/train.py --num_epochs 3 --saved_fn sfa4d_test_3epoch --checkpoint_freq 1 --print_freq 10 --batch_size 4 --dataset-dir ./DRadDataset --root-dir ./ --gpu_idx 0
```

**参数说明**：
- `--num_epochs 3`：训练 3 个 epoch
- `--saved_fn sfa4d_test_3epoch`：模型保存文件名前缀
- `--checkpoint_freq 1`：每轮保存模型
- `--print_freq 10`：每 10 个 batch 打印一次日志
- `--batch_size 4`：批次大小
- `--dataset-dir ./DRadDataset`：数据集相对路径
- `--root-dir ./`：项目根目录
- `--gpu_idx 0`：使用第一个 GPU

### 完整训练（300 轮）

```bash
source activate sfa3d && python sfa/train.py --num_epochs 300 --saved_fn sfa3d_8d_full_300epochs --checkpoint_freq 1 --print_freq 50 --batch_size 16 --dataset-dir ./DRadDataset --root-dir ./ --gpu_idx 0
```

> `--saved_fn sfa3d_8d_full_300epochs` 与仓库已分发权重的路径一致（`checkpoints/sfa3d_8d_full_300epochs/Model_sfa3d_8d_full_300epochs_epoch_163.pth`）：我们实际使用的是这次 300 轮训练中的**第 163 轮** checkpoint。

### 恢复训练

```bash
source activate sfa3d && python sfa/train.py --num_epochs 300 --saved_fn sfa4d_resume --checkpoint_freq 1 --print_freq 50 --batch_size 16 --dataset-dir ./DRadDataset --root-dir ./ --gpu_idx 0 --resume_path ./checkpoints/sfa3d_8d_full_300epochs/Model_sfa3d_8d_full_300epochs_epoch_163.pth
```

**训练输出目录结构**：
- 模型权重：`checkpoints/<saved_fn>/Model_<saved_fn>_epoch_N.pth`
- 优化器状态：`checkpoints/<saved_fn>/Utils_<saved_fn>_epoch_N.pth`
- 日志：`logs/<saved_fn>/log_train.txt`，TensorBoard：`logs/<saved_fn>/tensorboard/`

## ONNX 导出与推理

### 模型转换（注意参数名是 `--model` / `--output`）

```bash
source activate sfa3d && python sfa/export_to_onnx.py --model ./checkpoints/sfa3d_8d_full_300epochs/Model_sfa3d_8d_full_300epochs_epoch_163.pth --output ./onnx_models/sfa3d_163_fp32.onnx
```

仓库已附带导出好的 `onnx_models/sfa3d_163_fp32.onnx`（48.57 MB），无需重复导出。

### ONNX Runtime 推理（CPU 可跑，约 5.48 FPS）

```bash
source activate sfa3d && pip install onnxruntime && python sfa/run_onnx_inference.py --onnx_model ./onnx_models/sfa3d_163_fp32.onnx --dataset-dir ./DRadDataset --imagesets-dir ./DRadDataset/ImageSets
```

## 量化模型

### INT8 动态量化（48.57 MB → 12.27 MB，-74.7%；产物已随仓库分发：`quantized_models/sfa3d_163_int8.onnx`）

```bash
source activate sfa3d && python sfa/quantize_onnx_163.py --onnx_model ./onnx_models/sfa3d_163_fp32.onnx --output ./quantized_models/sfa3d_163_int8.onnx
```

脚本量化后自动用 `sample_data/` 真实样本对比 FP32 / INT8 检测结果（实测 3 样本检测框完全一致，热力图均值偏差 < 0.0002）。

> 注：`sfa/quantize_model_163.py` 为 PyTorch 量化路线，仅作对照——torch 动态量化不支持 Conv2d，本模型为纯卷积网络，实测压缩率 0%。
> 权重采用 QUInt8：QInt8 会生成 ConvInteger(S8S8) 节点，x86 CPU 版 onnxruntime 无该实现。

### 运行量化模型

量化产物为 ONNX 格式，直接用 ONNX Runtime 推理：

```bash
source activate sfa3d && python sfa/run_onnx_inference.py --onnx_model ./quantized_models/sfa3d_163_int8.onnx --dataset-dir ./DRadDataset --imagesets-dir ./DRadDataset/ImageSets
```

（`sfa/legacy/run_163_quantized.py` 为 PyTorch 量化路线的运行入口，已归档，仅作对照。）

## 常见问题

1. **路径问题**：确保使用相对路径 `./DRadDataset`，且在仓库根目录执行
2. **GPU 内存不足**：减小 `batch_size`（8 → 4 → 2）
3. **ImageSets 缺失**：脚本会尝试直接从 `velodyne/` 或 `label_2/` 枚举文件，但建议始终提供完整 `ImageSets/`
4. **恢复训练路径**：检查 `--resume_path` 指向的文件是否存在
5. **8D 数据识别**：`lidar_mapping.py` 按文件大小对 8/5/4 取模判断维度，文件损坏可能导致映射错误
